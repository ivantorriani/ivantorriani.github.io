Unknown Area Navigation

A multimodal perception pipeline for out-of-distribution autonomous navigation — published in the CS+AI Journal of Computer Science, Cal Poly San Luis Obispo.

Despite the name, deep learning models don't learn. Once trained, a model can only act inside the domain it was trained on. A navigation stack tuned on high-infrastructure urban driving has no idea what to do with a tractor on a rural road, or a pedestrian in a costume. As environments get less predictable, autonomous navigation gets less useful — exactly where it would be most valuable.

This is a four-phase program to let vehicles operate in out-of-domain environments — disaster zones, rural areas — where standard models fail. The phase documented here, and the one carrying published results, is the perception layer: rather than retraining or replacing an existing navigation system, it layers on top of one and handles the inputs the base detector was never trained on.

The insight driving the design is that a system doesn't need to identify an unknown object to act safely around it. It needs to notice that something is unknown, ask a more capable model whether the scene ahead is passable, and gate its own motion on the answer.

Pipeline

The persistence gate is the piece that makes this practical rather than merely possible. A candidate unknown must appear for eight consecutive frames before it counts as real. Object detectors flicker constantly, and without the gate every frame of noise would fire an API call. With it, detector jitter is filtered out before anything expensive happens, and queries are further held to a five-second cooldown.

Detecting what the model doesn't know

Three approaches were built and run head-to-head over an identical protocol: five known objects (scissors, cell phone, fork, knife, cup) and five unknown ones (thermometer, lighter, chapstick, keys, inhaler), each presented three times, for 30 trials per approach.

These were not three guesses evaluated once. The unknown-object detection feature went through four versions, each one a hypothesis formed from qualitative analysis of where the previous version failed, then validated with a controlled test against the same 30-trial protocol.

Confidence-thresholded YOLO-World won decisively at 93.3% accuracy and 93.3% F1. The more elaborate approach lost: running two open-vocabulary models and requiring them to agree cost 13 points of accuracy, because consensus turns any single model's miss into a system-wide miss.

The colour-histogram baseline is the instructive failure. Its precision looks survivable at 66.7% — but its recall is 13.3%. It missed 13 of 15 unknowns. And for navigation, recall is the metric that matters: a false alarm costs a wasted API call, while a missed unknown is a vehicle driving into something it does not understand. An approach can look tolerable on aggregate accuracy and still be unusable.

Which model judges the scene

Once an unknown persists, a frame goes to a vision-language model, which returns a structured JSON verdict: a scene description, a binary traversable / not-traversable call, and a justification. Six models were evaluated — four run locally, two through cloud APIs — against nine held-out scenes.

The aggregate numbers are close. The error analysis is what's worth reading: the two models fail in opposite directions. Gemini was over-permissive — it cleared a person in a morph suit standing beside a novelty pedestrian sign as traversable. It was also over-conservative in a different way, refusing a graffiti-covered bridge, having apparently read visual degradation as a proxy for structural unsafety. GPT's single miss ran the other way: it refused a clear road because a hitchhiker was standing on it.

Both were reliable on the unambiguous cases — fallen tree, flooded road, livestock in the road, aircraft blocking the road. The disagreements cluster entirely on scenes involving people behaving unusually, which is precisely the out-of-distribution category the system exists to handle.

Practical gap

All four local models — Qwen2-VL-7B, LLaVA-1.5-7B, Moondream2, InternVL2-2B — took between ten and thirty-plus minutes per image on CPU. Cloud APIs answered in two to five seconds. For a system whose entire purpose is deciding whether to keep moving, that difference isn't a tuning problem, it's a design constraint: on-vehicle inference without a GPU is off the table, which makes network availability a first-class architectural concern rather than a convenience.

This is the kind of result that only shows up if you actually build and measure the alternatives, and it changed the shape of the rest of the system.

System

  • DetectionYOLO-World (YOLOv8s-worldv2) open-vocabulary detection, 25% minimum confidence with a 50% known/unknown cutoff; NanoOWL (OWL-ViT) for the consensus variant at 0.20 IoU matching
  • Gating8-frame persistence requirement, 5-second query cooldown
  • InterpretationSix VLMs evaluated — Qwen2-VL-7B, LLaVA-1.5-7B, Moondream2, InternVL2-2B locally in fp16; GPT-4.1-nano and Gemini 2.5 Flash Lite via API
  • NavigationAprilTag fiducial pose estimation (115mm tags, calibrated intrinsics), ±75mm lateral dead-band, 100mm stop distance, with obstacle recovery logic
  • TestingProperty-based tests via Hypothesis — 5 declared properties × 100 generated examples, proving all six model backends parse verdicts and format output identically
  • StackPython, PyTorch, Ultralytics, OpenCV, transformers, pupil-apriltags

The property-based testing deserves a note. Six different model backends all had to produce the same downstream contract. Rather than spot-checking each, the shared parsing and formatting utilities were tested by declaring five invariants and letting Hypothesis generate a hundred random inputs against each — so a malformed response from any backend fails loudly instead of silently propagating a wrong traversability call into the navigation layer.

Limitations

  • The three subsystems were evaluated independently. The quantitative results above are per-subsystem; end-to-end integration is exercised by the demos but not separately measured.
  • A custom class-agnostic detection model was designed but not trained, so the open-set detection still leans on an open-vocabulary model rather than a purpose-built one.
  • The VLM comparison rests on nine scenes. It is enough to expose the opposite-failure-direction pattern, not enough to rank the models with confidence.
  • Cloud inference makes network availability a dependency — the local-model timing results show that removing it is not currently a viable trade.
  • Later phases of the program, including the meta-learning and few-shot adaptation work, remain in progress.
