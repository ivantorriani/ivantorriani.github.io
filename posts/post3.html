Understanding Embeddings, Encoding, Decoding (Simple / Byte)

July 24, 2025

Today I learned the concepts and application of LLM embeddings.

One of the big ideas is that LLM’s produce text one word at a time, based on the context of the previous few words. This is a concept called ‘sliding windows’, which I will get into later. It also explains why almost all LLM’s seem to ‘stream’ out words, where it seems like it’s typing it out, but it’s actually using context to write out words one at a time.

Usually, and I don’t understand how accurate my language is when I’m saying this, but I’ll call them the ‘datasets’ used to map word similarity are incredibly interesting. They are mapped in \( \mathbb{R}^{n} \) space, where you can expect certain pairings like Cat and Dog, or Cat and Mouse, to be relatively aligned. You may also find Dog and Bone in the same area, but not as close as something like ‘pet’. You’ll notice that higher level models like GPT have huge datasets mapping these similarities.

Now for the specifics. Obviously machines can’t work with words during training, so it is required to split sentences into tokens. So, the sentence “The Cat and the Mouse” would become [‘The’, ‘Cat’, ‘and’, ‘the’, ‘Mouse’] . Most novice computer scientists would say this is a simple text.split(‘ ‘) command, but to account for the multiple punctation that appears in text like ‘,’ ,’—‘, ‘:’, etc… you have to use a more robust re.split('([,.:;?_!"()\s]|--)' .

Now, each word is mapped to a vector representing a space in \ ( \mathbb{R}^{n} \). The entire implementation is below. 


        class SimpleTokenizerV1:
            def __init__(self, vocabulary):
                self.str_to_int = vocabulary
                self.int_to_str = {i:s for s,i in vocabulary.items()}

            def encode(self, text):
                preprocessed = re.split('([,.:;?_!"()\s]|--)', text)
                preprocessed = [
                    item.strip() for item in preprocessed if item.strip()
                ]
                ids = [self.str_to_int[s] for s in preprocessed]
                return ids

            def decode(self, ids):
                text = " ".join([self.int_to_str[i] for i in ids])
                text = re.sub(r'\s+([,.?!"()\'])', r'\1', text)
                return text

However, these custom classes can only include words you feed it. It’s more optimal to just use a premade class from tiktoken or something in order to handle more diverse text and save a lot of time.

The final concept I learned today was sliding windows used for created training data. As I mentioned earlier, models are trained by predicting the next word based on context. “The Cat and the” sentence could have a high change of being followed by “Hat” or “Dog”, for example. However, for the machine to make this assumption, it has to be trained on a huge amount of text data so that it can make the correct assumption. In encoded format, we would give the context label as something like [1523, 123, 521, 123] and a truth label [942] . After a lot of examples it should link the context to the label make an accurate prediction.
